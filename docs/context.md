# 上下文、压缩与真实用量

默认配置：基础消息窗口10条，真实输入用量达到10000 Token后评估压缩，之后增长3000 Token才再次评估；50000触发强制压缩，总窗口保护上限60000，预留2000给回复。面板“设置与备份”可以调整前四项。

基础窗口包含当前消息，不是把每轮截成10条。运行时还会加入当前话题未压缩的原文、明确引用链和本话题图片。话题、图片、摘要按宠物及会话隔离；图片保留原发送者和原消息ID，直接作为主模型的多模态输入。每次实际回复都会自动提供基础窗口内最近两条图片消息的原图，无需命中任何看图词；较早图片与最新图片相隔超过5分钟时不占用这一轮近期图片名额。明确引用优先；基础窗口没有图片时可继续使用话题原图。多人图片分别附来源，由主模型结合问题判断所指，仍有歧义时澄清；更多图片可用READ读取。近期背景图片不会被自动永久钉入当前人的旧话题。原图归属不依赖“距离最近的人”。

话题关联优先使用消息关系和发送者。较长且有歧义的新问题可交给廉价决策模型选择候选话题，主动接话判断也可以返回话题ID。模型返回的ID必须属于当前宠物、当前会话。当前规则仍可能误判自然语言换题，聊天检查页可以查看实际选入的消息和图片来源。

压缩由决策模型判断并生成结构化摘要，保留目标、决定、待解决问题、不确定信息和来源。常规压缩保留最近10条，强制压缩至少保留最近2条，并保护当前问题、明确引用和原图。仅压缩已处理的连续前缀，不越过排队中的新消息；失败保留旧摘要及游标。摘要不会删除原文，也不直接写入人物画像或好感度。摘要更新后重新按新请求的真实用量开始评估。

模型用量记录来自服务实际返回的 `usage` / `usageMetadata`，输入、输出、总量及缓存用量分别记录。未返回的字段显示“未知”，服务明确返回0才显示0。每次请求记录模型、种类、会话和话题；主回复还关联请求快照。汇总只相加已知字段，并记录缺少输入用量的调用次数。早期版本已有的用量记录不会被追溯改写。

**请求前尚未接入服务端的精确预计数接口。** 本地以文本UTF-8字节及图片尺寸留出请求预算，这只是保护值，不是实际Token或账单；图片的真实计数取决于服务。因而60000是本地配置的保护预算，不能声称是服务分词器精确计算的60000 Token。过大时先压缩，再去掉可选细节裁图、较早背景消息，保留原图；必要内容仍过大则明确要求分段，不发送超出本地保护预算的请求。

面板“聊天检查 → 话题与真实用量”提供话题摘要、压缩状态及来源、请求选入和省略记录、图片消息归属、逐次真实用量。手动压缩按钮会调用模型，仍保留原文。上下文压缩与阶段性人物画像总结是独立流程。

原生桥接的接入范围见项目README；上下文模块不会补齐尚未接入的语音、视频或合并转发能力。
