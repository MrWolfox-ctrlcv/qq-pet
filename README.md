# QQ Pet

基于 **官方 QQ 客户端 + 本地原生桥接** 的 AI 宠物，配套本地网页控制面板。自有源码采用 [Apache License 2.0](LICENSE)。

## 功能

- 群聊和私聊；可配置被 @ 回复、廉价模型判断主动接话，以及每群的判断间隔和冷却。
- 提示词、模型与工具权限面板；每只宠物有独立配置和数据范围。
- 图库与表情包分类、编号、标签、检索、实际候选图预览、原图/GIF 发送、隐藏和恢复。
- 开放素材管理工具后，可在聊天中收录当前或明确引用的图片，修改标题与标签，删除和恢复素材。
- 绘画支持已有图库参考图，作品自动入库；支持聊天式图片模型接口和 Agnes 专用生图接口，需自备服务密钥。
- 来图直接作为多模态图片输入交给主对话模型，不先转成文字摘要；细节任务附原图局部放大。先发图再单独请求描述时，按近期明确指向关联，保留原作者，歧义时请求澄清。
- 按 QQ 号维护人物画像与好感度；阶段性会话总结有消息来源，人工锁定字段不被自动覆盖。
- 持久化接收任务、发送状态、会话来源与媒体归属；不把历史图片当作后来发言者的新图。
- 本地记忆检索、备份、修订与恢复。可选本地 BGE；没有权重时明确降级为关键词检索。

## 当前边界

原生桥接已经在 Windows x64 的 QQ 9.9.25-42941 上验证文字、群消息、图片、GIF、@ 和指定消息读取。它依赖 QQ 的内部接口与特定 V8 ABI，升级客户端后需要重新验证，**不是跨版本稳定的官方 SDK**。

后台按宠物支持多账号；每个原生桥接需要匹配自己的 QQ 进程和账号。不同 Windows 用户下双开客户端的完整部署尚未验证。QQ 空间、签名、频道、合并转发、原生语音和视频读取尚未在这套原生桥接中完成；媒体处理模块支持的格式不等于当前 QQ 接入已提供对应能力。

此发布只包含源码和合成测试资料，没有部署者的账号、人设、会话、画像、模型密钥、网络地址或图库。详见 [公开版的数据边界](docs/privacy.md)。

## 快速开始

需要 Node.js 24 或更高版本；原生 QQ 桥接需要 Windows x64 和 Python 3.10+。

```powershell
npm ci
npm run build
npm run create:pet -- --account <机器人QQ号> --owner <主人QQ号> --name "My Pet"
npm start
```

打开 `http://127.0.0.1:4780`。管理员登录令牌在本地 `data/admin-token.txt`，不会放在链接里。新宠物初始暂停，连接和工具权限默认关闭；先在“设置与备份”配置模型，再按 [原生桥接说明](bridge/README.md) 连接已经通过官方 QQ 完成登录的账号。

提示词、画像、图库、表情包与阶段性总结都在面板里管理。聊天检查页展示阶段性总结及来源；设置页可以调整主动回复、总结频率和工具权限。

默认数据目录为 `./data`，可用 `PET_DATA_DIR` 指定；端口用 `PET_PORT` 指定，默认 4780。`PET_HOST` 默认 `127.0.0.1`。可按需通过自己的 Tailscale 网络转发这个本地端口，项目不预设任何私人服务器地址。

## 开发

```powershell
npm run check
npm test
npm run build
```

测试使用临时目录和合成账号，不连接真实 QQ 或付费模型。网页交互测试可另行执行 `npx playwright test`，需要预先安装 Playwright Chromium。

## 目录

| 目录 | 内容 |
| --- | --- |
| src/ | 宠物运行时、HTTP API、SQLite、模型与媒体工具 |
| apps/web/ | Vue 控制面板 |
| bridge/ | 原生 QQ 桥接、匹配进程的手动挂接入口 |
| scripts/ | 创建宠物、准备独立桥接配置、可选旧数据导入 |
| tests/ | 合成资料的本地测试 |
| docs/ | 接口、数据结构、检索与公开版说明 |
